This repository squash-merges pull requests, so a pushed branch syncs by merging `main` into it, and pushed commits are never rewritten — the branch's intermediate history vanishes at the squash, so merge commits cost nothing.

A sync lane lands on the feature branch as a merge commit (`gh pr merge --merge`), never as a squash — or, where the repository disallows merge commits, by fast-forwarding the feature branch to the lane's tip (`git push origin <lane-tip>:<feature>`, after merging the feature branch into the lane if it has moved), which GitHub records as the PR's merge: a squash keeps the merged tree but drops `main` as a parent, so the feature PR's merge base never moves, its diff swallows everything `main` changed, and the conflicts the sync resolved come back. The sync is landed only when `git merge-base --is-ancestor <synced-main> origin/<feature>` answers yes, where `<synced-main>` is the `main` commit the sync merged — the second parent of the sync's merge commit, which the sync lane's branch keeps, and `refs/pull/<number>/head` keeps after that branch is deleted. A squashed sync is recovered with `git merge -s ours <synced-main>` on the feature tip: same tree, ancestry restored. Aim that recovery only at `<synced-main>`, never at a `main` that has moved since: `-s ours` would record main's newer commits as merged while discarding their content.
