## Deliverable prose is written in the deliverable's voice

When the document embeds a passage the build will carry into a shipped artifact nearly as is — a vision statement destined for the docs, copy destined for a page — write that passage under the style guide that binds the shipped artifact, never in the document's own register. The reader approving that passage is approving the deliverable's words, so they must already be the deliverable's words.

## Put removal on the table before drafting rules

When an element needs new governing rules invented to stay coherent — an edge case with no stated bar, a mode nobody has defined — the recommendation must weigh striking the element entirely, not only candidate rules for it. A rarely used case that complicates something clear is usually better cut, and a mode that earns its keep later can arrive as its own project.
