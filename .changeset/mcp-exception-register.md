The exception register for an MCP server now holds three kinds of exception
instead of one. Tools that stand outside the rule that every tool wraps a
business function gain a third reason, the handoff: a read-only tool that
answers the link to a browser page, so an assistant can send the person to
a job that stays in the browser. A tool may also wrap a business function no
page calls when only an assistant needs it, such as reporting a request no
tool could serve. And a real capability that needs a password, a raw secret,
a sign-in or two-factor step, or a payment is kept in the browser by a
written reason and a page link, instead of being passed off as something
that isn't a capability. The `mcp-server` skill, the parity criterion in the
Definition of Done, and the register `install` scaffolds all describe the
three kinds, and the parity check they describe counts a capability kept in
the browser as claimed.
