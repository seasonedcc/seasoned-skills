Today’s way, and where it breaks

Today there is exactly one way to learn this way of working: its author explains it, live, one person at a time. Nothing written stands in for that conversation. The package’s README speaks to one narrow reader — someone checking whether a codebase is ready to install — and never says what the workflow is as a way of working. Everything else in the repository is written for the agents that execute the work, in a dialect tuned for machines, not for a person reading over coffee. The workflow’s goals and the vision it is building toward live only inside its founding shaping document, where no newcomer would think to look. So the people closest to it — the ones already running it daily — operate it without grasping the full arc, and anyone further out has no way in at all.

The outcome test

What has to be true afterwards for this to have worked. Write it so anyone can check it without asking us — an observable difference in someone's day, not a feature list.

Why now

The workflow just became a package anyone can install — and the circle of people meeting it is widening right now. One co-founder already works in a project that runs it daily; another, long used to working AI-first, is next; and beyond them stand industry peers whose feedback would sharpen the workflow while it is still young and cheap to change. None of them can be handed anything today but a conversation. Every week without a written way in, the author stays the only bridge — the exact failure the workflow itself was built to end for code.
